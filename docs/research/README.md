## TL;DR

- Официальный десктоп-клиент Б24 для Linux существует с 2022 (DEB/RPM; на Arch — AUR `bitrix24`, перепаковка). Писать «ещё один клиент» незачем. Слабые места клиента: виджеты маркетплейс-приложений (телефония и др.) работают только в веб-версии; deep-link `bx://` официально задокументирован только для botContext; поведение под Wayland/Hyprland никем не проверено.
- REST API закрывает сценарии трей-плагина: входящий вебхук (scope `im`) + поллинг `im.v2.Event.get` для сообщений; CRM-события — `event.bind` offline + `event.offline.get` (нужны локальное OAuth-приложение + админ). Realtime-доставка системных событий без публичного HTTPS-обработчика невозможна — только поллинг. REST гейтится тарифом (коммерческий + подписка Маркетплейс). Лимиты: 2 req/s, batch 50.
- Свободная ниша: демон «Б24 → нативные уведомления + счётчик в waybar» не существует. Omarchy 4 даёт готовые кирпичи: `omarchy-notification-send --exec` (клик по тосту → открыть URL карточки), waybar custom module, `omarchy-launch-webapp`.

## Рекомендация (после проверки оракулом)

Порядок важнее архитектуры:

1. **Гейт №0 (1–2 часа, до строчки кода):** (а) создать входящий вебхук и curl-ом проверить `im.v2.Event.subscribe/get`, `crm.lead.list`, непрочитанные (`im.recent.*` или что найдётся) — одним заходом закрывает тарифный гейт и все «не подтверждено» ниже; (б) поставить AUR `bitrix24` и посмотреть трей/уведомления/шаринг под Hyprland. Результат решает: узкий нотификатор / полноценный демон / стоп.
2. **MVP v0 — webhook-only (фокус: задачи и чаты, CRM не в скоупе):** сообщения через поллинг `im.v2.Event.get` (упоминания — парсингом BB-кода `[USER=id]`); задачи через дельта-поллинг `tasks.task.list` по `CHANGED_DATE` в трёх ролях; счётчики — `im.counters.get` + `im.recent.list UNREAD_ONLY`, дедлайны — фильтры `STATUS=-1` и диапазон `DEADLINE` (всё подтверждено доками с вебхук-примерами, файл 04); single-instance лок, чтобы второй инстанс демона не воровал события. Спека: [../SPEC.md](../SPEC.md).
3. OAuth-приложение + `event.offline.get` — только после того как v0 доказал ценность (тянет админа + публичный HTTPS-callback).
4. Click-to-call — отдельный проект (REST не набирает номер, нужен свой SIP-стек), в бэклог; дизайн демона держать с чистым event-bus.

Демон (systemd user unit, Go/Rust) + нативные кирпичи Omarchy (`omarchy-notification-send --exec`, waybar custom, `omarchy-launch-webapp`) — без изменений. Electron/Tauri-обёртка — только если упрёшься в потолок (свой трей, кнопки в уведомлениях).

## Открытые вопросы (закрываются гейтом №0)

- Тариф портала: есть ли доступ к REST.
- Live-проверки: работает ли `::LOGIC OR` в фильтре задач; меняется ли `CHANGED_DATE` после комментария; URL чата `/online/?IM_DIALOG=chat{ID}`; коды `notify_event` у упоминаний.
- AUR `bitrix24` на Hyprland: трей, шаринг экрана, XWayland vs native, какая URL-схема регистрируется.
- Рендер ли произвольных action-кнопок в нотификаторе Omarchy 4 (`notify-send -A`).
